# Golden-master (characterization) harness

Locks today's observable behaviour of the CPT app so that every extraction out of
`src/lib/cpt-app/legacy-controller.js` and the later restyling can be proven non-breaking by a
mechanical check instead of by eye. Design: `worklog/refactor/03-characterization-tests.md`;
implementation notes: `worklog/refactor/04-harness-implementation.md`.

```
tests/golden/
├── fixtures/          committed inputs, generated by scripts/golden/make-fixtures.mjs (seeded)
│   ├── cpt/           synthetic CPT files (GEF / CSV / XLSX) + one state-injection fixture
│   ├── projects/      saved projects (*.madep.json, v0.5.3 format, built through the controller)
│   ├── models/        solver model fixtures copied from scripts/fixtures/ (for the solver suites)
│   └── manifest.json  file → sha256, role, PRNG seed, generator notes
├── node/<suite>/      Node-tier goldens: <case>.json | .txt | .csv | .svg (see suites below)
├── browser/<journey>/ browser-tier goldens: <step>.state.json | .dom.txt | .png (+ downloads, payloads)
├── vendor/            chart.umd.js — Chart.js 4.4.1 from the CDN URL of src/routes/+page.svelte
├── wasm.sha256.json   pin of static/wasm/**; golden:check refuses to run against a different engine
├── tolerances.json    numeric tolerance classes (pure / wasm / iterative / browser)
├── CHANGELOG.md       every intentional golden update: date, commit, reason, affected cases
└── .actual/           git-ignored; normalised actual of every mismatch, for git diff --no-index
```

## Running

| Command | What it does |
|---|---|
| `npm run golden:check` | run every Node suite, compare, exit 1 on FAIL / NEW / MISSING (≈ 30 s) |
| `npm run golden:check -- --filter layers` | one suite; `--filter 'layers/short.*'` one case pattern (glob) |
| `npm run golden:check -- --list` | list suites with their tolerance class |
| `npm run golden:update -- --filter <glob>` | rewrite only the failing/new cases (add a CHANGELOG entry!) |
| `npm run golden:record` | rewrite everything (baseline only) |
| `npm run golden:fixtures` | regenerate fixtures (bit-identical), fetch Chart.js, pin WASM hashes |
| `npm run golden:wasm-check` | verify the WASM pin only |
| `npm run golden:browser` | browser journeys (Tier C) in check mode: `playwright test --config tests/e2e/golden.config.mjs` (≈ 30 s + dev-server start) |
| `npm run golden:browser:record` | rewrite every browser golden incl. PNGs (`GOLDEN_MODE=record`); `GOLDEN_MODE=update` rewrites only the failing/new files |
| `npm run verify:core` | the fast existing verifiers (nen6740, stratigraphy, import-review, project-io, scia-db4, qc-only, retaining, wasm, bishop-phase-a) |
| `npm run test:all` | svelte-check + verify:core + golden:wasm-check + golden:check + Playwright e2e |

On a mismatch the runner prints the first 25 differences per case as `path: expected → actual (Δrel)`,
writes the normalised actual to `tests/golden/.actual/<same path>`, and a summary table per suite.
`git diff --no-index tests/golden/node tests/golden/.actual/node` shows the full picture.

## Suites (Node tier)

Tier B = the monolith itself loaded under Node (`scripts/golden/lib/load-controller.mjs`: Vite
`createServer({middlewareMode}).ssrLoadModule` + a hand-rolled DOM stub, `Chart` stub, synchronous
`requestAnimationFrame`, download/alert capture, auto-confirmed import-review dialog). Tier A = pure
modules imported directly.

| Suite | Tier | Locks |
|---|---|---|
| `import` | B | GEF/CSV/XLSX parsers + `applyParsedCpt` through `loadGEF` (rows, wt/elev/xy sources, meta, import-review text, meta card, raw chart configs, banner); seeded `loadDemo()`; demo fixture ⇔ `loadDemo()` parity |
| `classification` | B (+A) | `runClass()` × 5 methods per profile (classified rows, assumed-Rf bookkeeping, metrics/notes text, layer preview/column SVG); pure `classify*` on a reading grid |
| `layers` | B | `detectLayers()` smart/simple × 5 methods, minThk 0.3/1.0, sensitivity 0.9/1.3, manual edit path (`changeSubtype`, `editL`), `#lb` text, compatibility warnings |
| `model` | B | `hsParams`/`khParams` over {A,B}³ × {sb260, def} via the real setters, `#ma` text |
| `tuning` | B | `runTuning`/`fitLayer`, accept/reject, slider helpers, `#tuningArea` text |
| `exports` | B | `exportCSV`, `exportPlaxisCommands` (+ its alert), `exportPlaxisCpt`, `saveProject` snapshot, download file names |
| `stage6-shared` | B | `stage6Defaults()` in full, `ensureStage6State` on fresh / partial / v0.5.2 state, app switch |
| `stage6-bearing/pile/settlement/dewatering/beam` | B (+A) | each app's analysis as cached by `renderStage6` for {default, heavy, edge} configs, the clamped config, rendered text; `bearingAtDepth`, `layerAtDepth`, `PILE_CONSTANTS`, `computeSubgradeReaction` |
| `report` | B | `buildStage7Payload()` after the full Stage 2–6 chain (full for `layered`, digests of the row tables/annex analyses elsewhere), `isStage7Payload`, `openStage7Report` side effects |
| `retaining` | A | 5 wall types × {default, overrides, RK0, RK2} × 2 profiles: `buildRequest` → WASM → `computeEmbeddedStructural` → views (text) → scene → note → drivability (vibratory, impact, Alm & Hamre, data sheet) |
| `project-io` | A (+B glue) | `buildProjectSnapshot`/`validateProjectSnapshot`/`applyProjectSnapshot` per project fixture, round-trip identity, `loadProjectFromFile → afterLoad` glue |

Profile fixtures (`role: profile` in the manifest) run through every suite; the layered import
variants (`kpa-units`, `corrected-depth`, CSV, XLSX) only through `import`; `trailing-qc-only` and
`wt-above-surface` are skipped by the Stage 6 / report suites (their difference is upstream).

Some duplicated parts are stored as `{"<digest>": sha256[0:24], bytes, n}` instead of in full (the
retaining note's copy of the engine result, project snapshots' CPT rows, the report's row tables for
fixtures other than `layered`, the diagram vectors of the RK-variant retaining results). A change
still flips the golden; the readable diff lives in the suite that owns the data.

## Browser journeys (Tier C, `tests/e2e/golden-journey.spec.mjs`)

The real app in Chromium (Playwright, own config `tests/e2e/golden.config.mjs`: port 5299, one
worker, no retries, nl-BE / Europe/Brussels, 1500×950). Each journey is a linear list of steps; a step
locks `state.json` (`window.__golden.captureState()` — `PROJECT` minus `charts`/`chartsReady`, the
active CPT once under `active`, its `stage6Cache` under `cache`, normalised by the same
`normalize.mjs`, compared with `tolerances.browser`), `dom.txt` (`innerText` of `#cptTabs` and the
active `.panel`, or step-specific containers, whitespace-collapsed, time masks applied) and a
secondary `png` (canvases masked, `maxDiffPixelRatio` from `tolerances.browser`; `GOLDEN_VISUAL=off|soft|strict`,
default `soft` = reported, never blocking — fonts differ between macOS and the Linux CI renderer).

| Journey | Start | Steps |
|---|---|---|
| `demo-journey` | "Load demo" button under a seeded `Math.random` (mulberry32, manifest seed) | 01-loaded → 02-classified(-method) → 03/04 layers (+ subtype `<select>` edit) → 05 model (default, alpha A / stiffness A) → 06 tuning (+ acceptFit 0) → 07 bearing/pile/settlement/dewatering/beam (default + one `setStage6Field`) → 08 retaining walls: 5 types × every result tab → 09 drivability → 10 calculation-note tab + payload → 07-bishop model + stability search → 11 exportCSV / PLAXIS commands / simulated CPT / saveProject downloads (+ alerts) → 12 Stage 7 payload + report tab → 13 final |
| `gef-import-journey` | `fixtures/cpt/layered.gef` through the real file input and the import-review dialog (00-import-review) | same |

Determinism (all in the spec / `scripts/golden/lib/browser-capture.js`): seeded `Math.random`, a
`Date` shifted to a fixed epoch (still advancing — Chart.js needs a moving clock), Chart.js served
from `vendor/` with `Chart.defaults.animation = false`, the analytics script neutralised, and
state-predicate waits (`retwall.status === 'done'`, `drivability.status !== 'running'`,
`bishop.progress.running === false && results`) — never `waitForTimeout`. Large parts that are locked
in full at the step that produced them (`data`, `classified`, `tuning`, `retwall.result`,
`bishop.results`, every `cache.*` analysis) are stored as `{"<unchanged-since>": step, "<digest>": …}`
at later steps. Mismatches go to `.actual/browser/<journey>/` and the test fails at `finish()` with
the readable diff; a golden on disk that the journey no longer produces is `MISSING`.

## Normalisation and masks (`scripts/golden/lib/normalize.mjs`)

Applied at record and check time, identically:

- keys sorted at every level; `undefined` and functions dropped (`dewatering.waterTableAtDistance`,
  chart tick formatters); `NaN`/`±Infinity` stored as strings; typed arrays → arrays;
- **dropped keys**: `charts`, `chartsReady` (Chart.js instances);
- **masked keys** (`"<masked>"`): `generatedAt`, `savedAt`, `capturedAt`, `timing`, `totalMs`, `solveMs`,
  `generatedMs`, `elapsedMs`, `runId`, `dataUrl`, `copyMessage`, `copyTone`, any `*Ms`, any `_private`
  key except `_maxStage` (stage-nav unlock — behaviour);
- **masked strings**: `wall_*/drain_*/region_*` and `bc-*` entity ids → `<id>`; `stage7-report:*`,
  `retaining-note:*`, `soilin-report:*` storage keys → `<key>`; PNG data URLs → `<png>`; ISO timestamps → `<iso>`;
  inside strings, `<n> ms` → `<ms> ms` (the Bishop completion message embeds `timing.totalMs`);
- browser DOM text additionally masks nl-BE date-times (`1 jan 2026 01:00` → `<datetime>`) and the
  `_YYYYMMDD-HHMM` stamp of the saved-project file name (`scripts/golden/lib/journey.mjs` `TEXT_MASKS`);
- text goldens: `\r\n` → `\n`, single trailing newline; HTML is reduced to visible text
  (`scripts/golden/lib/html-text.mjs`) so a restyle that only changes tags/classes is invisible
  while wording, numbers and order stay locked.

Tolerances (`tolerances.json`): `pure` rel 1e-9 / abs 1e-12 (same code path must be identical);
`wasm` and `iterative` rel 1e-6 / abs 1e-9; text goldens exact. Key sets and array lengths must match
exactly in every class. **Never widen a tolerance to make a check pass** — find the reordered
floating-point operation or the changed default.

## Refactor protocol (design §5)

Per extraction step out of `legacy-controller.js`:

1. `git switch -c refactor/<n>-<module>` from the branch tip (goldens are green there by construction).
2. `npm run golden:check` — must be green before touching code.
3. Extract: move functions into `src/lib/cpt-app/<module>.js`, import them back, keep every `window.*`
   name in `legacyApi` unchanged for this step.
4. `npm run golden:check` (Node tiers, ~30 s).
5. `npm run golden:browser` when the step touches rendering, Stage 6, project-io or report
   (browser tier — separate task; skip for pure-compute moves once step 4 is green).
6. Review any diff:
   - only masked/volatile fields differ → the mask is incomplete → fix `normalize.mjs`, not the golden;
   - numeric diff within 1e-9 in a `pure` suite → **not allowed**; a pure move must be bit-identical;
   - numeric diff across WASM/iterative → allowed inside the suite tolerance only;
   - structural diff (key added/removed) → behaviour change → split out of the extraction commit.
7. If a behaviour change is intended: commit the extraction with goldens untouched (green), then commit
   the fix separately with `npm run golden:update -- --filter <suite>` and a `CHANGELOG.md` entry
   (`date sha suite: what changed and why — cases: …`). CI refuses `tests/golden/**` changes without one.
8. When the extraction exposes a new pure function, add a Tier A case for it in the same PR — this is
   how the harness migrates from Tier B (controller under Node) to Tier A as the monolith shrinks.
9. Commit with DCO sign-off; PR passes `.github/workflows/ci.yml`.

Restyling: `state`/text goldens must not move at all; HTML view templates in
`retaining/results/*` and `panels/*` are locked as text in `retaining` and are updated in a dedicated
commit when a template is intentionally reworded; screenshots (browser tier) are the only tolerant signal.

## Determinism

`make-fixtures.mjs` is seeded (mulberry32, seed in `manifest.json`), the controller is loaded once per
process with a synchronous `requestAnimationFrame`, `Math.random` is replaced only around
`loadDemo()`, and every volatile field is masked. Baseline: `golden:record` followed by two
`golden:check` runs with zero diffs. Any future flake is a determinism leak — fix the mask or the
seeding, never the tolerance.

Known app behaviour documented by the goldens (not fixed here, the harness locks the code as it is):
`fixtures/cpt/layered-comma.csv` (`;`-separated, comma decimals) is parsed with `,` as the delimiter
because `detectDelimitedTextSeparator` scores the comma decimals as extra columns → 341 garbage rows
(`node/import/layered-comma.csv.json`). A fix is a behaviour change with its own golden update.
